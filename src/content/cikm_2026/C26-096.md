## Коротко

LLMAW4CDSR использует семантические user/item representations от LLM, чтобы адаптивно оценивать полезность каждого source domain для целевого sequential recommender.

## Задача и мотивация

Богатый данными домен помогает разреженному только при наличии релевантного знания. Равномерное смешивание источников может переносить шум. Даже LLM-enhanced embeddings не решают эту проблему, если contribution каждого домена остаётся одинаковым. Работа делает source weighting явной частью переноса.

## Как работает метод

1. LLM создаёт семантически обогащённые representations пользователей и товаров.
2. Эти признаки задают guidance для согласования source и target domains.
3. Source-domain weighting mechanism оценивает вклад каждого источника в целевую задачу.
4. Более релевантные домены усиливаются, шумные подавляются при моделировании последовательных предпочтений.

## Эксперименты и результаты

По аннотации проведены эксперименты на четырёх cross-domain датасетах; LLMAW4CDSR превосходит state-of-the-art CDSR и LLM-based baseline. Числа источников, точные веса, стоимость LLM подготовки и проценты улучшения не раскрыты.

## Ограничения и практический смысл

Для собственной оценки стоит проверить уровень персонализации weighting: один источник может быть полезен одной группе пользователей и вреден другой. Также важно не подменять семантическую релевантность статистической насыщенностью домена. Аннотация не позволяет утверждать, что weighting уже решает все такие случаи.

Метод полезен системам с несколькими потенциальными источниками данных, где отрицательный перенос важнее простой нехватки capacity. Пилот стоит строить на контролируемом добавлении и удалении источников и отдельно оценивать пользователей с разным междоменным поведением. Мониторинг весов во времени поможет увидеть, реагирует ли модель на смену полезности доменов или в основном запоминает статическую схему смешивания. Полезно заранее определить fallback для отсутствующего источника: оценка при удалении одного домена покажет, насколько веса отражают устойчивые предпочтения, а не зависимость от конкретного набора данных.

## Вопросы авторам

1. Веса источников вычисляются для всего target domain, для пользователя или для конкретного шага истории, и каковы компромиссы между этими уровнями?
2. Как вы отделяете семантическую релевантность source domain от его размера и качества поведенческих данных при оценке contribution?
3. Насколько устойчив weighting при добавлении заведомо нерелевантного источника и резкой смене интересов внутри целевого домена?
4. Какой baseline с обычными embeddings и тем же weighting module показывает дополнительную пользу именно LLM semantic guidance?
