## Коротко

MISTRec представляет товар одним collaborative и четырьмя semantic slots. LLM восстанавливает замаскированные historical slots и предсказывает полностью скрытые slots будущего товара. Далее идёт сопоставление с каталогом. Это генерация continuous representation с retrieval-style grounding, а не autoregressive decoding semantic ID.

## Задача и мотивация

Новый ID-token не имел item-смысла во время общетекстового pretraining LLM. Если обучать его только угадыванию следующего identifier, связь с содержанием и поведением может оставаться слабой. Авторы задают структуру item-представления заранее и добавляют reconstruction. Дополнительно они ослабляют penalty для правдоподобных альтернатив, ошибочно воспринимаемых как отрицательные товары.

## Как работает метод

1. Offline GRU4Rec даёт collaborative memory. Отдельные embeddings метаданных образуют semantic memory bank; learned queries собирают из него несколько semantic slots. CF и semantic признаки проецируются в hidden dimension LLM разными heads.
2. В history случайно скрывается часть slots, но у каждого настоящего товара сохраняется хотя бы один видимый slot. Reconstruction-query block добавлен после истории, что позволяет decoder-only LLM восстанавливать пропуски с доступным контекстом; future-query block полностью замаскирован.
3. Предсказанные future slots сравниваются с однотипными candidate slots по cosine similarity. User-adaptive веса смешивают scores, затем добавляется item bias. Основной loss — full-catalog cross-entropy, плюс отдельное grounding каждого slot и reconstruction loss.
4. FNR выбирает hard negatives и оценивает их близость к target по semantic/CF memory. Подозрительные false negatives получают меньший вес в дополнительном contrastive loss. Важно: основной full-catalog ranking loss продолжает считать non-target товары отрицательными; FNR не удаляет их из всей оптимизации.

## Эксперименты и результаты

Beauty, Sports и Toys проверены с одинаковыми filtered sequences и full-catalog evaluation. Последний item пользователя — test, предпоследний — validation; train-prefix содержит минимум два historical items. Backbone — Qwen2.5-1.5B с LoRA, максимум истории 20, по четыре semantic slots и до 16 metadata aspects на товар (§4.1). Небольшие каталоги содержат примерно 12–18 тыс. товаров; результаты не устанавливают масштабирование до миллионов.

Таблица 2: Beauty Recall@10 — 0,1042 против 0,0941 у SETRec, около +10,74% относительно; NDCG@10 — 0,0565 против 0,0525 у EAGER. Sports Recall@20 — 0,0754 против 0,0675 у SETRec. На Toys NDCG@5 — 0,04642 против 0,0464 у EAGER: разность практически нулевая относительно приведённого разброса, поэтому её нельзя подавать как убедительное статистическое превосходство.

В таблице 3 Beauty Recall@10 снижается до 0,0904 без MSA, 0,0941 без FNR, 0,0886 без CF-slot и 0,0943 без semantic slots. Collaborative evidence остаётся существенно важным. На long-tail Beauty (G4) Recall@10 — 0,070 против 0,050 у CoVE, но группы построены по накопленной массе взаимодействий, не равному числу товаров и не строгому cold-start.

## Ограничения и практический смысл

Моя оценка: structured continuous slots дают понятный интерфейс между item evidence и LLM. Однако информация о category/brand уже присутствует во входных метаданных: probing показывает её сохранение, а не доказательство причинного disentanglement. CF memory фиксируется при semantic intervention, что тоже нужно учитывать при интерпретации стабильности. FNR опирается на similarity heuristic, способную ослаблять полезные трудные negatives. Для применения важны размер memory banks, обновление новых товаров, ANN-совместимость user-dependent slot weights и полная inference-стоимость больших каталогов. Онлайн A/B нет.

## Вопросы авторам

1. Сохраняется ли выигрыш при одинаковом числе векторов и параметров у holistic continuous baseline и slot-модели?
2. Как выполнять ANN-retrieval с user-dependent slot weights и насколько точно оно воспроизводит full-catalog ranking?
3. Как проверяется качество FNR на размеченных альтернативных предпочтениях, а не только по похожести memory embeddings?
4. Каково поведение CF/semantic slots при обновлении каталога и сдвиге самого collaborative memory bank, а не только замене brand metadata?
