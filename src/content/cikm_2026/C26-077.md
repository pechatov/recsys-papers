## Коротко

OPD выделяет обучаемую ось популярности и ортогональное ей collaborative представление, позволяя менять popularity prior без переобучения. Финальные результаты статьи включают смешение нормализованных scores Base и OPD, что важно для оценки реальной цены метода.

## Задача и мотивация

При неравномерной частоте товаров embeddings могут сжиматься вокруг общего направления. Такая anisotropy особенно мешает редким items, чьи признаки получают мало положительных обновлений. Проблема не только в geometry: обычный dot product смешивает соответствие интересам и общий popularity prior, поэтому serving не позволяет отдельно управлять этим компромиссом.

## Как работает метод

1. Для товара фиксируется standardized `log(1+training frequency)`. Это внешний data-grounded popularity scalar, который не обучается совместно с рекомендациями. Модель вводит единичный learnable вектор e_pop.
2. User state и item embeddings проецируются на e_pop; из исходных векторов вычитаются эти проекции. Dot product ортогональных остатков образует collaborative часть score. Ортогональность задана алгебраически, но сама по себе не гарантирует статистическую независимость от популярности.
3. Пользовательский scalar affinity оценивается через attention pooling всех hidden states вдоль e_pop. Popularity score умножает этот affinity с offset b, частоту товара и общий коэффициент γ. γ обучается, а при inference γ и b можно перекалибровать по validation без переобучения embeddings.
4. Full-vocabulary cross-entropy дополняется необязательным InfoNCE на ортогональных user representations с crop/mask views. Для итогового inference авторы складывают per-user z-normalized scores Base и OPD по unseen candidates (§3.7.3). Поэтому таблица основных результатов описывает полный score ensemble, а не изолированную замену одного dot product.

## Эксперименты и результаты

Amazon Beauty, Toys и Sports обработаны 5-core фильтрацией и leave-one-out. Ранжирование проводится по всем товарам кроме user training history, без sampled negatives. Общий SASRec-style backbone имеет hidden size 64, два слоя и два attention heads, max length 50. Base уже использует cosine scoring и contrastive objective; это сильнее исходного vanilla SASRec. Для Ours и Ours w/o OPD приводятся средние и sample standard deviation по пяти seeds.

В таблице 1 на Sports HR@10 равен 0,0602 ± 0,0010 против 0,0570 ± 0,0011 у собственного Base без OPD. NDCG@10 растёт с 0,0332 до 0,0354. Относительно опубликованного ICSRec HR@10 0,0566 заявленный выигрыш равен 6,36%; сравнение с собственным сильным Base даёт около 5,61%. Эти величины отвечают разным вопросам и не должны смешиваться.

Geometry analysis показывает, что большая часть общей isotropy уже достигается Base с contrastive training. Для tail items Sports средний pairwise cosine снижается с 0,067 у Base до 0,022 в OPD collaborative subspace (таблица 3), однако effective rank не превосходит Base повсюду (таблицы 4–5). Это не подтверждает тезис о безусловном улучшении любого geometry-показателя.

Sweeps γ и b показывают accuracy–exposure trade-off: уменьшение popularity weight улучшает холодные частотные deciles, но может снижать общий NDCG. Catalog coverage, средняя training frequency и Gini рассматриваются совместно, а не как эквивалентные определения fairness. Дополнительные D+1 обучаемых параметра относятся к OPD-модулю; это не полная цена score ensemble и нормализации по candidates.

## Ограничения и практический смысл

Практический плюс — понятная ручка для управления popularity concentration после обучения. Это позволяет явно сравнить разные продуктовые operating points вместо скрытого изменения всей модели.

Моя оценка: ортогональный остаток может содержать нелинейные признаки популярности, а одна глобальная ось не обязательно описывает сезонные и доменные эффекты. Exposure fairness на логах не доказывает справедливость для поставщиков или полезность пользователю. Для внедрения нужно проверить drift частот, эффективность candidate-pool z-normalization и выигрыш модуля без смешения с Base при одинаковом serving budget.

## Вопросы авторам

1. Какой вклад OPD остаётся без score ensemble с Base и при одинаковом training/serving budget?
2. Насколько из collaborative subspace можно восстановить популярность нелинейным probe после удаления e_pop?
3. Как обновлять замороженный frequency prior при сезонности и новых товарах без нарушения выбранного γ/b operating point?
4. Сохраняется ли accuracy–coverage frontier после переноса full-catalog z-normalization на ограниченный retrieved candidate pool?
